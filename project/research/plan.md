# 検証の計画書（BTC・ETHの売買ロジック）

最終更新：2026-11-24

試したいロジックを先に一覧にしておき、1つずつ同じ物差しでバックテストしていくための計画書です。定番から奇抜なアイデアまで324件を並べています。検証の進み具合と結果は「8. 一覧」に書き込んでいきます（第1回：2026-11-23、優先「高」の21件。第2回・前半：2026-11-23、AとEの優先「中」24件。第2回・後半：2026-11-23、BとKの優先「中」17件。第3回・前半：2026-11-24、CとHの優先「中」16件。第3回・後半：2026-11-24、DとFの優先「中」20件。第4回・前半：2026-11-24、MとLの19件。第4回・後半：2026-11-24、Iの14件とE17。第5回・前半：2026-11-24、Nの12件（評価は2019年から）。第5回・後半：2026-11-24、OとPの26件）。

- 一覧の正本は `plan.csv`（1行1パターン）。このファイルの「8. 一覧」は `project/tools/plan_tool.py` が `plan.csv` から作る
- 検証の数字は `results.csv`、考察は `README.md` に残す

## 1. 目的

- 年単位で負けない
- 落ち込み（含み損込み）が小さい
- 大勝ち頼みではなく、勝ちを重ねる
- 対象はBTC・ETH（Vantage CFDが中心。国内現物とも比べる）
- 手作業なら、朝9時か12時半の1回の操作で回せる

## 2. 進め方

1. 一覧から、優先度の高い「未」を1回に10〜20件選ぶ（`plan_tool.py next`）
2. 「3. 共通の決まり」でバックテストする
3. 「4. 合格の基準」で判定し、状態と結果を書き込む（`plan_tool.py set`）
4. 合格した部品は、組み合わせ（M）の候補にする
5. 最後まで残った形は、これからの値動きで記録をとる（フォワードテスト。まだ行わない）

## 3. 共通の決まり

| 項目 | 内容 |
|---|---|
| データ | Binance（BTC・ETH、2017年8月〜）の15分足・30分足・1時間足・日足。ほかの市場はYahoo |
| 期間 | 2018年1月〜。前半（2018〜2022年）で設定を選び、後半（2023年〜）で確かめる |
| コスト | Vantage CFD：往復0.05%、買いのスワップ年25〜35%（日本時間6時ごろをまたぐごと）、売りは0%。国内現物：往復0.15%、スワップなし |
| 1回の量 | ATR1本分の値動き＝資金の0.5%（単利）。損切りのある形は、損切りにかかると資金の0.5%を失う大きさ |
| 約定 | 信号は足が終わってから見る。次の足の始値か逆指値で入る。足の中の値動きの順番がわからない時は、甘め・厳しめの両方で計算するか、15分足で確かめる |
| 見る数字 | 年平均、最大の落ち込み（含み損込み）、効率、安定度（月の損益の平均÷ばらつき）、マイナスの年、最悪の年、プラスの月、取引回数、勝率、平均の勝ち・負け、前半と後半 |
| 銘柄 | BTCとETHの合計に加えて、それぞれ単独でも見る |

## 4. 合格の基準

| 段階 | 条件 |
|---|---|
| 1次（ふるい） | 年平均がプラス（コスト込み）。前半・後半の両方でプラス。取引は年20回以上（長期の形は除く） |
| 2次（頑丈さ） | 設定を前後にずらした結果の7割以上がプラス。BTC・ETHのどちらでもプラス。安定度0.8以上。負ける年は2年まで |
| 3次（第一候補に足せるか） | 値幅ブレイクとの月の損益の相関が0.5未満。足すと安定度が上がるか、負ける年・落ち込みが減る。値幅ブレイクの量を増やしただけの形より良い |
| 採用の候補 | 3次まで合格し、朝の1回の操作か簡単な仕組みで続けられる |

## 5. 「たまたま良く見える」を防ぐ

300通り以上を試すと、偶然だけで良く見えるものが必ず出ます。5%の確率なら16個ほどです。これまでにも、9日EMAで「負ける年がない」のは50日平均の時だけ、という例がありました。そこで次の3つを必ず行います。

- 前半で選び、後半で確かめる。後半の成績を見てから設定を変えない
- 設定を前後にずらし、周りも良い「山の形」かを見る。1点だけとがって良いものは落とす
- 合格の基準を段階にして、1次の合格だけで採用しない

本物の実力かを測る物差しとして、ランダムな売買（N15・O12）とも比べます。
